# ENH-009 — One-shot database clone

Date: 2026-08-05 · Status: done · Source: `ENHANCEMENTS.md` ENH-009

## Goal

Add `POST /admin/clone-db?from=&to=` that clones a database in one server-side
step, instead of the manual `export-db` → `create-db` → `import-db` dance.
Useful for dev/preview seeds and safe experimentation off a live database.

## Design

Reuse the existing snapshot primitives end-to-end — no new wire format, no new
DSL, no client mirror:

1. `require_admin` (same constant-time key check as `export-db`/`import-db`).
2. Reject `from == to` (400), unknown `from` (404), and an already-existing `to`
   (400, so clone never silently overwrites).
3. Export `from` (`state.schemas.get` + `snapshot::export_database`) **before**
   creating `to`, so a read failure leaves nothing behind.
4. `db::create_database(to)` (registers + creates side tables), then
   `snapshot::import_database(to, jsonl)` (pushes the schema + replays docs with
   ids/`createdAt`/`version` preserved), then `state.schemas.put(to, applied)`.
5. On an import failure after `to` is created, invalidate the cache and return
   the error — the empty `to` is left for the operator to delete, consistent with
   `import-db`'s no-cleanup behavior.

Scope matches `export-db`/`import-db` exactly: schema + documents only. Storage
blobs and scheduled transactions are not part of the snapshot format and are not
copied. Admin-only; no wire/DSL change ⇒ no client mirror required.

## Server — `server/src/admin.rs`

- `CloneDbParams { from, to }` + `clone_db` handler (inserted beside
  `export_db`/`import_db`).
- Route `.route("/admin/clone-db", post(clone_db))`.
- `tests/admin_test.rs` — `clone_db_round_trips_schema_and_documents` (schema +
  per-table docs match source, ids/createdAt/version preserved) and
  `clone_db_rejects_self_clone_missing_source_and_existing_target` (400 / 404 /
  400).
