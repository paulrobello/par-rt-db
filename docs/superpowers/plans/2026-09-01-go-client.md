# Go Client (go-client) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `go-client/` — the sixth par-rt-db client (Go 1.23): wire types, query/mutation/schema DSL, HTTP one-shot client with storage, WS `/sync` client with channel subscriptions, admin client, optimistic updates, and a Go in-memory engine that makes go-client a full sixth runner of the wire-corpus (no permanent skips).

**Architecture:** Static hand-written Go wire types (the sixth implementation of `server/src/protocol.rs`), `wire.JSONValue` for dynamic documents, subpackage layout where only `wsclient` imports a third-party dependency (`github.com/coder/websocket`), channel-based subscriptions with a manager goroutine, and an in-memory engine mirroring the shape of `rust-client/src/in_memory/` and swift's `InMemory*.swift`.

**Tech Stack:** Go 1.23+, `encoding/json` only (no codegen), `net/http`, `github.com/coder/websocket` (wsclient only), stdlib `testing` + `net/http/httptest`.

**Spec:** `docs/superpowers/specs/2026-09-01-go-client-design.md` — read it first. The plan argues from the spec; the spec's §4 casing contract tables are the authority for every wire shape below.

## Global Constraints

- **Mirror source of record:** `server/src/protocol.rs`, `core/src/wire.rs`, `core/src/mutation.rs`, `server/src/dsl.rs` are the contract. `rust-client/src/wire.rs` (+ `query.rs`, `mutation.rs`, `schema.rs`, `http.rs`, `ws.rs`, `error.rs`, `cursor.rs`, `admin/mod.rs`) is the structural model for the port. When any field name, tag, or omission rule below conflicts with the server file, **the server file wins** — stop and fix the plan's type, never guess.
- Wire casing is load-bearing and deliberately non-uniform. Replicate per-type exactly per spec §4. Never normalize.
- Every wire type carries a doc comment `// Mirrors server/src/protocol.rs::<Type>` (or the owning file for non-protocol types).
- Zero third-party dependencies outside `wsclient/`. `wire`, `dsl`, `errors`, `httpclient`, `inmemory`, and the root package import stdlib only. Enforced by the dep-guard in Task 12.
- No `panic` in library code; every failure is a returned `error` / `*errors.RtDbError`. No `os.Exit` in library code.
- Go 1.23 floor (`go 1.23` in go.mod). `gofmt` clean; `go vet ./...` clean.
- Omit-vs-null: `omitempty` ONLY where the server has `skip_serializing_if`; a plain nullable field (e.g. `AuthedUser.name`) marshals unconditionally with `null` when absent.
- Unknown-field rejection on every wire type (serde `deny_unknown_fields` analog) via `wire.StrictUnmarshal`.
- int64 travels as decimal strings: use `wire.Int64`. Bytes travel base64 (stdlib default).
- Do NOT touch root-repo files (`Makefile`, `.github/workflows/ci.yml`, `README.md`, `CLAUDE.md`, `FEATURE_MATRIX.md`, `wire-corpus/README.md`, `.pre-commit-config.yaml`, `CONTRIBUTING.md`, `docs/clients.md`, `docs/RELEASING.md`) until Task 30. Everything before that lives under `go-client/`.
- Commits: conventional style (`feat(go-client): …`), one per task, test-green first. Run commits with a ≥600 s tool timeout — the repo pre-commit runs clippy and takes >2 min. Never add a co-author trailer.
- Test command (all pre-Task-30 tasks): `cd /Users/probello/Repos/par-rt-db/go-client && go test ./...`. Live tests (Task 29) additionally need `-tags=live`.
- Corpus fixtures are read-only. Never edit `wire-corpus/**` to make a runner green; a divergence is a client bug (fix the client) or a stale fixture (stop and report — the owner decides).
- Never run `make dev-db-clean` or drop databases you didn't create.
- No `go-client/v*` tags get pushed. Tagging is an owner decision tied to ENH-031.
